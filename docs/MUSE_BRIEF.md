# Muse への依頼文（ユーザーがそのまま渡す用）

もちへ。Claude が bot を約300個作ってバックテストで評価し、ペーパーで動かす候補を厳選した。
仕様書は GitHub の wataaass/trade-bot、ブランチ `claude/effort-estimation-z1y12z` の `docs/HANDOFF_MUSE.md`。
売買判断の参照実装は `tradebot/handoff.py`（検証と同じ判断になることを `tests/test_handoff.py` で確認済み）。

お願いしたいこと:

1. 仕様書の「採用」2つ（A. UPRO⇄BIL、B. UPRO と BIL の比率を値動きに合わせて決める版。どちらも `handoff.daily_plan` で動かせる）を、米国ペーパー口座 1459674 の新しい枠として動かす。各枠の元手は本番と同じ $2,000 にする（手数料の効き方が本番と同じになるように）
2. moomoo 証券（日本）の本番口座で、売った代金をその場で次の買いに使えるか（受け渡し前の買付余力に入るか）を確かめてほしい（手数料 0.132%・上限 $22 は公式ページで確認済み）
3. 余力があれば「実験枠」2つ（C. TQQQ⇄BIL、D. 個別株モメンタム6-1 上位10）と、B の 15% を 20% にした B′（`handoff.daily_plan("B′", ...)`。A と同じかそれ以上の手取りで下落が浅かった候補）も別枠で動かす
4. 枠ごとに、比較対象の持ち続け（A・B は SPYM か VOO、C は QQQM）と並べて「開始時点＝0%」の累積で報告する
5. 仕様書の数字や判断におかしな点があれば指摘してほしい（レビュー係として）

運用上の注意（仕様書の3章）:

- 判定は引けの終値、発注は**翌営業日の引け間際（NY 15:45〜15:55、日本時間 冬5:45〜／夏4:45〜）に成行**。寄り付き約定は実物の UPRO で年 1〜2 ポイント不利だった（仕様書3章、改良の記録32.）
- A・B の200日線の判定には「非対称の遊び」がある: 200日線を割ったらすぐ逃げ、200日線の +1% を超えたら戻る（間にいる日は前の状態のまま）。`handoff.trend_on` 参照
- 損切りはしない。売るのは判定が変わったときだけ
- A・B・C とも -40% で報告、-60% で運用を見直す（B も新しい持ち方に合わせて A と同じにした）。自動停止にはしない（検証では普通に起きる深さのため）
- A・B・C は同じ200日線で動くので、同じ日に一斉に切り替わる（分散にはならない）
- この型は米国株でしか効かなかった（日経平均・米国以外の10か国では持ち続けに負けることが多い）。日本の口座（1570 日経レバなど）には移さない

Claude 側の5枠は 11/7 に停止済み。口座に残っている Claude 枠の建玉の扱いは、ユーザーが決める。

## 更新点（2026-11-08 夜）

- A・B の200日線の判定に「非対称の遊び」を入れた（割ったらすぐ逃げ、+1% を超えたら戻る）。売買が3〜4割減り、2003年〜の手取りが上がった
- すべての数字を本番と同じ元本 $2,000 で計算し直した（元本が大きいと手数料の上限 $22 が効いて甘く出る）
- この型は米国株でしか効かない（日経平均・米国以外の10か国では持ち続けに負けることが多い）。金利が高いほど優位は縮む
- もちの月末型（SPY⇄IEF、SMA250）とも同じ物差しで比べた: 守りの型（7.7%、最大下落 -25%）で、A・B（攻めの型）とは目的が違う。B 50%＋月末型 50% は 10.2%・最大下落 -36% で、持ち続け（9.7%・-55%）より良い組み合わせになる（仕様書1章）
- **発注のタイミングを変更**: 寄り付きではなく、翌営業日の引け間際に成行。寄り付きは実物の UPRO で年1〜2ポイント不利だった
- 判定は毎日行う（週1回に減らすと年1〜2ポイント不利だった）
- moomoo の K線（`autype=1`）の SPY の終値は Yahoo と完全に一致した。1回の取得（370本）で判定に足りる。K線の返り値は `handoff.closes_from_moomoo` でそのまま判断関数に渡せる
- 確定申告をするなら外国税額控除も受ける（持ち続けが年0.2〜0.4ポイント良くなり、A・B との差はその分縮む）
- 退避先は BIL でも SGOV でもよい（SGOV が年0.1〜0.2ポイント良い）
- 試してやめたことも含めた記録は `reports/improvements.md`（1〜45、冒頭に目次）

## 更新点（追加）

- **B・B′ の持ち方を変更（推奨）**: 倍率を下げるとき SSO・SPYM に乗り換えず、UPRO と BIL の比率で持つ（2倍の月は UPRO 2/3 ＋ BIL 1/3、1倍の月は UPRO 1/3 ＋ BIL 2/3）。目標の比率が変わった日だけ差の分を売買する。全部売り替えないので税金と売買が減り、税引き後で B は年 +1.0、B′ は年 +0.4 ポイント（実物の ETF、2010〜）。参照実装は `handoff.target_weights` と `handoff.plan_rebalance`、詳しくは仕様書の3章 B と `reports/improvements.md` の49.
- **B・B′ の比率を連続的に決める（改良50）**: UPRO の比率 = min(1, 15% ÷ 前月末の20日の値動き)、残り BIL（B′ は 20%）。前回の目標から 0.1 未満の変化は無視。8つの時代すべてで3段階の版を上回った（B は下落がやや深くなる期間あり）。参照実装は `handoff.upro_share(spy, k, prev)` と `handoff.target_weights`。詳しくは仕様書3章 B、`reports/b_weights.md`
- 使う銘柄は A・B・B′ とも UPRO と BIL の2つだけになる
- 毎日の手順（判定 → 注文 → 翌日に引き継ぐ状態）を `handoff.daily_plan` にまとめた。移植はこの関数を基準にすると間違いが少ない
- 毎月積み立てても、持ち続けに対する優位は変わらない（`reports/improvements.md` の48.）
- moomoo の米国株の取引手数料（0.132%、上限 $22）は公式ページで確認した。検証の前提と同じ
- moomoo のアプリには引け成行（MOC）注文がある。UPRO・BIL は NYSE Arca 上場で、締切はニューヨーク時間 15:50（15:45 以降は取消不可）。API からは成行しか確認できていないので、bot は今どおり引けの5〜15分前に成行で出す
- 新しい B は、発注の遅れ・約定のずれ 0.3%・借入コスト +1% のどの悪条件でも持ち続けを上回った（旧版は ETF で下回ることがあった）。点検の目安は A・B・B′ 共通で -40%（報告）／-60%（見直し）
